# ADR-020: Storage kernel and domain repositories

**Status:** accepted

**Date:** 8 August 2026

**Depends on:** ADR-001, ADR-003

## Context

The repository audit recorded `packages/database` as the largest obstacle to
extracting durable runtime state (§4.2): it depends _upward_ on seven domain
packages — `agent-events`, `change-contracts`, `change-passport`,
`role-protocol`, `role-recommender`, `verification-runner`, and `contracts`.
A store that knows domain logic inverts the intended layering, and R5 was
blocked on deciding what to do about it.

Inspection shows the package is really two things wearing one name:

```text
storage kernel        client.ts, migrations/, event-store, snapshot-repository
                      → depends only on @roleflock/contracts + better-sqlite3

domain repositories   ~40 repositories under repositories/
                      → import the domain packages whose rows they map
```

The kernel is already clean. `EventStore` imports one type, `EventEnvelope`,
and the SQLite handle. The upward dependencies come entirely from repositories
that map rows to domain objects, which is a reasonable thing for a repository to
do and an unreasonable thing for a storage engine to do.

## Decision

Treat the two halves differently rather than refactoring the package.

**The storage kernel's dependencies are frozen at `@roleflock/contracts`.** The
SQLite client, migrations, `EventStore`, `SnapshotRepository` and reducers may
not import a domain package. Durable runtime state is built on the kernel, so
this is the boundary that actually needed deciding, and it already holds.

**The domain repositories keep their upward imports**, recorded as an accepted
layering exception rather than pretended away. Moving forty repositories into
their domain packages would be a large mechanical change with no behavioural
benefit, would touch every consumer, and would collide with the runtime work it
was supposed to unblock.

## Consequences

### Positive

- R5 proceeds without a refactor: durable runtime records use the kernel, which
  is already at the right layer.
- The rule is enforceable by inspection — one directory, one allowed import.
- A future relocation of the repositories stays possible and is not made harder.

### Negative

- `packages/database` keeps a dependency shape that reads wrong from its
  `package.json` alone, and a reader has to know this ADR to see why.
- The exception could be used to justify adding more upward imports.

## Constraint for new code

New durable runtime state — graph runs, node runs, loop attempts, invocation
identity — is defined in `contracts` and persisted through the kernel. It must
not require a domain package, because the runtime is meant to execute any
compiled workflow, not only coding ones.

## Alternatives considered

**Move repositories into their domain packages.** Correct in principle;
rejected as a prerequisite. It is a large change with no behaviour improvement,
and doing it while extracting runtime state would mix two risky migrations.

**Move domain types into `contracts`.** Would flatten the graph but turn
`contracts` into a dumping ground and couple unrelated domains through it.

**Do nothing and leave the question open.** Rejected: R5 needed to know whether
it could build on `EventStore`, and leaving that unanswered would have meant
guessing.
